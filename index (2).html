how it works

Recursive descent in, recursive construction out

The front-end is two passes over the same grammar: a parser that builds a syntax tree, and a builder that walks it once to assemble the automaton.

// grammar, lowest to highest precedence
union  → concat ('|' concat)*
concat → star+
star   → base '*'*
base   → literal | '(' union ')' | 'ε'

// construction, one rule per node type
build(node):
    match node.type:
        literal:  new q0,q1;  q0 −sym→ q1
        epsilon:  new q0,q1;  q0 −ε→ q1
        concat(A,B):
            fuse A.accept with B.start into one state
            start ← A.start ,  accept ← B.accept
        union(A,B):
            new q0,q1
            q0 −ε→ A.start,  q0 −ε→ B.start
            A.accept −ε→ q1, B.accept −ε→ q1
        star(A):
            new q0,q1
            q0 −ε→ A.start,   q0 −ε→ q1
            A.accept −ε→ A.start,  A.accept −ε→ q1

Why merge states instead of adding an edge?

For concatenation, Thompson's original construction identifies A's accept state and B's start state as the same state, rather than linking them with an extra ε-transition. It is a small optimization with a real payoff: it keeps the automaton's size linear in the length of the expression instead of adding an unnecessary state at every join.

The size guarantee

For a regular expression of length n, this construction produces at most 2n states and at most 4n transitions — never more. That bound holds regardless of how deeply the expression nests unions and stars, which is exactly what makes Thompson's construction the standard first stage of a regex engine: parse once, build once, size stays predictable.

What happens next, conceptually

This ε-NFA is not yet a fast matcher — matching against it means tracking a whole set of "current states" and repeatedly taking ε-closures, which is exactly what the string tester on this page does. A real engine typically continues on to subset construction (NFA → DFA) or simulates the NFA's state set directly, the way Thompson's own implementation in the original ed/grep lineage did.
